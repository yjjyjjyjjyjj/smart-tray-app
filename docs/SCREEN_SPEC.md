# 아마따 화면 명세

Android 실행에서는 실제 Classic 검색·페어링·연결 상태, 알림 권한 안내, 시스템 알림 미리보기, 실제 연결/체험 모드 전환을 추가로 제공합니다. 브라우저는 기존 가상 장치 목업을 유지합니다. 센서 해석과 LED·살균 명령은 펌웨어 연동 대기 상태입니다.

공통 웹 UI는 브라우저에서 가상 데이터로, Android에서는 Kotlin의 Bluetooth·위치·날씨·시스템 알림과 연결해 동작합니다. **프로토콜 미확정 — Arduino 펌웨어 분석 후 확정 예정**.

## 화면과 이동

| 화면 | 진입·경로 | 목적 및 UI | 사용자 상호작용 |
| --- | --- | --- | --- |
| 연결과 위치 설정 | 최초 실행 또는 `#connect` | Bluetooth 검색·연결과 날씨용 위치 권한·휴대폰 위치 상태를 같은 화면에 표시 | 장치 선택, 위치 허용·날씨 확인, 시스템 위치·앱 권한 설정 열기, 설정 완료 또는 나중에 설정 |
| 홈 대시보드 | `#home` | 앱 이름, 가상 연결 상태, 최상단 외출 전 체크, 현관문, 마지막 수신, 간결한 최근 활동 | 트레이 상세, 전체 관리, 알림 설정, 모든 기록, 알림함 |
| 트레이 관리 | `#trays` | 트레이 카드 2개와 별도 우산 카드, 중앙 정렬 번호 아이콘, 별칭, 물건 상태, LED·살균 ON/OFF | 이름 변경 모달, 트레이 상세 |
| 트레이 상세 | `#detail/1` ~ `#detail/2` | 번호·이름, 상태, 무게, 변경 시각, LED·살균 설정 | 이름 편집, LED·감지·문 열림 스위치, 살균·자동 실행·문 열림 스위치, 5·10·20·30초, 두 가지 미리보기 |
| 알림 설정 | `#notifications` | 전체·문 열림·미수거·2개 트레이·우산 스위치, 묶음 안내, Android 시스템 알림 형태의 미리보기 카드 | 스위치 즉시 저장, 상단 시스템 알림 배너 시연, 트레이 확인 이동 |
| 활동 기록 | `#activity` | 날짜별 시간 내림차순 이벤트, 기기에 최신 200개 저장·재실행 복원 | 전체·거치·제거·현관문·알림·장치 필터 |
| 설정 | `#settings` | 우리 집 프로필, 장치·알림·앱 메뉴 | 각 설정 진입, 설정을 유지한 연결·위치 설정 다시 열기 |
| 장치 관리 | `#device` | 장치 이름, 가상 연결, 마지막 수신, 2개 로드셀 센서·측정값 | 연결 해제·재연결·검색 |
| 알림함 | `#inbox` | 세션의 가상 알림 최대 50개, 시각·읽음 상태 | 모두 읽음, 알림 설정 이동 |
| 앱 정보 | `#about` | 앱 목적, 연결·위치 이용 안내, 준비 중인 장치 기능, 앱 설정·기록 저장 안내 | 뒤로 가기 |
| 이름 편집 | 트레이의 연필 또는 상세의 이름 변경 | 현재 이름 입력, 1~16자 안내 | 공백 거부, 저장·취소, 관련 화면·알림 동기화 |
| 개발자 패널 | 설정·사이드바 버튼 / 단축키 D / 콘솔 `SmartTrayApp.openDeveloper()` | 개발 중에는 버튼을 기본 표시. `?dev=0`에서는 버튼과 빈 공간을 만들지 않음. 별도 우측 드로어에서 가상 데이터 조작 | 연결, 문, 물건, 무게, 센서, 미리보기, 알림, A–D 시나리오 |

모바일 하단 탭은 **홈 → 트레이 → 기록 → 설정**입니다. 데스크톱은 동일한 목적의 좌측 내비게이션을 제공합니다. 상세 화면의 뒤로 버튼과 브라우저 뒤로 가기가 동작합니다. 직접 상세 URL로 진입했다면 관련 목록 또는 설정으로 이동합니다. 알 수 없는 경로·트레이 번호는 안전한 기본 화면·트레이로 처리합니다.

## 추가 화면의 이유

- **알림함:** 알림 배너가 사라진 뒤에도 미수거 안내와 시뮬레이션 결과를 검토하기 위해 추가했습니다.
- **앱 정보:** 앱 이용 방법, 현재 사용할 수 있는 기능과 준비 중인 기능, 설정과 기록의 저장 범위를 안내합니다. 브라우저 체험과 Android에서 같은 앱 중심 문구를 사용하며, 개발 구조와 메이커톤 시제품 설명은 표시하지 않습니다.
- **별칭 편집 모달:** 화면 이동 없이 이름을 변경하고 입력 검증을 제공하기 위해 추가했습니다.
- **개발자 드로어:** 테스트 조작과 일반 사용자용 앱 경험을 분리하기 위해 추가했습니다.

권한·실패 안내와 연결 끊김·센서 오류는 별도 화면을 늘리지 않고 해당 연결·장치·홈 화면의 상태로 표현합니다.

## 공통 컴포넌트와 디자인

- 라이트 모드, 청록색 브랜드, 따뜻한 회색 바탕, 흰 카드, 연한 초록색 상태 표시.
- `css/style.css`의 동작 스타일 다음에 `css/interface.css`를 로드합니다. 공통 디자인의 색상·글자·여백·카드·버튼·스위치·배지와 반응형 규칙은 이 파일에서 관리합니다.
- 홈 체크 카드는 진한 초록색 요약 헤더와 밝은 보관 공간·날씨 영역으로 구분합니다. 모바일 상세의 센서 요약은 아이콘·이름을 나란히 배치해 설정까지의 스크롤을 줄입니다.
- 뒤로·화면 동작 버튼은 상단 도구 행에, 제목·설명은 그 아래에 배치합니다. 설정 메뉴는 아이콘·설명·오른쪽 화살표의 열을 일정하게 유지합니다.
- CSS, 로컬 SVG 및 생성 후 앱에 포함한 브랜드 PNG를 사용합니다. 실행 중 외부 폰트·CDN·이미지 API를 호출하지 않습니다. [브랜드 아이콘](BRAND.md)은 웹 헤더·앱 정보·Android 실행 아이콘에 적용합니다.
- 360~430px 우선 반응형 레이아웃. 640px 이하에서는 세로 트레이 카드, 900px 이하에서는 하단 탭을 제공합니다.
- 상태는 색상과 텍스트로 함께 표시합니다. 주요 버튼·모바일 탭은 충분한 높이를 제공합니다.
- 입력 레이블, 키보드 포커스, 모달 Tab 순환·Escape, 스크린리더 상태 알림, `prefers-reduced-motion`을 지원합니다.
- 하단 탭·개발자 패널은 safe area를 고려합니다. 긴 이름은 줄바꿈하며 HTML을 이스케이프합니다.

기본 별칭은 **1번 트레이·2번 트레이**입니다. 각 트레이에 자유롭게 별칭을 지정하며, 물건 종류를 식별하는 의미로 사용하지 않습니다. 기록은 “{별칭} 트레이에 물건이 놓였어요” / “{별칭} 트레이에서 물건이 없어졌어요”, 미수거 알림은 “{별칭} 트레이에 물건이 남아있어요. 외출 전에 확인해주세요.”로 표시합니다. 미수거 알림의 여러 칸은 각각의 이름을 쉼표로 묶습니다. 기록과 알림 모두 이미 ‘트레이’로 끝나는 별칭에는 ‘트레이’를 중복해서 붙이지 않습니다.

홈의 첫 카드는 외출 전 체크입니다. 물건이 남은 **트레이 수**와 두 칸의 상태·별칭, 별도 우산 공간을 표시하며, 첫 줄은 1·2번 트레이 두 열, 둘째 줄은 두 열 전체 너비의 우산 공간입니다. 각 칸을 누르면 상세로 이동합니다. 현관문 카드에는 LIVE 문구를 표시하지 않습니다. 제품 일러스트 대신 트레이 번호와 상태를 사용합니다. 전체 트레이 카드는 트레이 메뉴에서 제공하고 홈에서는 반복하지 않습니다. 최근 활동은 최대 3개의 내용·시간만 보여주며 상세 정보는 기록 메뉴에서 확인합니다.

트레이 카드의 살균 상태는 현재 동작 중이면 `살균 ON`, 정상이면서 멈춰 있으면 `살균 OFF`, 현재 상태를 알 수 없으면 `살균 —`입니다. 설정 활성화 여부와 현재 동작 상태는 구분합니다.

홈의 보조 문구, 트레이 안내, 알림 설명, 설정·앱 정보와 공통 푸터에 “외출할 때 한두 개씩 깜빡 두고 가는 물건을 한 번 더 챙겨준다”는 목적을 짧게 담습니다.

## 데이터·오류·빈 상태

| 상황 | 표시 및 처리 |
| --- | --- |
| 물건 있음 / 없음 | 상태 배지, 보관 중 / 비어 있음 안내 |
| 연결 안 됨·해제됨 | 상단 배지, 경고 배너, 카드 확인 불가. 과거 무게는 장치·상세에서 이전 값이라고 명시 |
| 수신 지연 | 전체 수신 또는 칸별 측정이 목업 기준 45초를 넘으면 업데이트 지연. 미수거 판정 제외 |
| 센서 오류 | 해당 칸 센서 확인 필요. 무게는 이전 값. 정상 칸만 알림 평가 |
| 수신 대기 | 측정 전 / 데이터 수신 대기. 정상 수신 전에는 물건 유무를 확정하지 않음 |
| 연결 실패 | 원인·다음 행동 안내, 장치 재선택 및 다시 검색 |
| 활동·알림 없음 | 각 목록의 아이콘·빈 상태 문구 |
| 필터 결과 없음 | 기록 없음과 다른 필터·시뮬레이션 안내 |
| 빈 이름·범위 밖 무게 | 입력 오류 및 유효 범위 안내 |
| 저장 차단·손상 | 기본값 복원 또는 세션 유지, 저장 불가 토스트 |
| 실제 기능 미지원 | 앱 정보의 준비 중인 장치 기능 안내, 실제 연결 화면의 센서 수신 대기 및 제어 미지원 안내 |

## 시뮬레이션 검증

일반 알림은 **닫힘 → 열림**에서만 평가합니다. 같은 열린 문을 여러 번 눌러도 중복 생성하지 않습니다. 다시 닫고 열면 새로운 이벤트로 평가합니다. 알림이 켜진 칸의 최신 정상 상태가 `물건 있음`인 경우 해당 트레이의 별칭을 하나로 묶습니다. 문 열림 알림도 켜져 있으면 미수거 알림에 통합하며 두 개를 만들지 않습니다. 미수거 대상이 없을 때 문 열림 알림만 따로 발생할 수 있습니다.

| 버튼 | 준비하는 상태 | 기대 결과 |
| --- | --- | --- |
| A | 1·2번 트레이에 물건 있음, 알림 활성화, 닫힘 후 열림 | 1·2번 트레이 별칭을 포함한 한 개의 미수거 알림 |
| B | 1번 트레이에만 물건 있음, 해당 트레이 알림 꺼짐 | 1번 트레이 미수거 없음. 문 열림 안내만 발생 |
| C | 2칸 모두 없음 | 미수거 없음. 문 열림 안내만 발생 |
| D | 1·2번 트레이에 물건이 있는 초기값 준비 후 연결 해제 | 현재 센서 상태 확인 불가, 신규 문 이벤트·미수거 알림 없음 |

시나리오 버튼은 알림 설정을 재설정하고 저장합니다. 수신 중단 체크는 즉시 오래된 상태를 만들어 지연 안내를 검증합니다. LED·살균 미리보기는 정상·최신 센서일 때 설정 스위치와 별개로 직접 실행할 수 있습니다. 이는 브라우저 내 일시적 미리보기이며 실제 장치에 설정을 전송하지 않습니다.

## 시스템 알림 미리보기

실제 Android 알림의 작은 앱 아이콘·앱 이름·수신 시각·제목·내용·동작 버튼 구성을 재현합니다. 알림 설정의 예시 카드와 미리보기 버튼·가상 문 열림의 상단 배너는 같은 컴포넌트를 사용합니다. “앱 내부 알림 미리보기” 대신 “Android 시스템 알림” 및 “미리보기”로 안내합니다. 브라우저 목업이라는 설명은 카드 밖에 표시합니다.

상단 배너는 약 8초 후 사라지고, 알림함에는 이력이 남습니다. 키보드 포커스가 배너 안에 있으면 자동으로 닫지 않습니다. 닫기 버튼·Escape로 닫을 수 있습니다. 본문 또는 확인 버튼을 누르면 한 칸은 상세, 여러 칸은 트레이 목록, 문 열림만 있는 경우는 홈으로 이동하며 읽음 처리합니다. 설정 저장 같은 일반 피드백은 하단 토스트를 사용합니다. 실제 운영체제 알림·브라우저 알림 권한·서버 푸시를 구현하지 않습니다.

## 우산과 날씨·문 열림 시간

- 홈: 트레이 2칸 + 우산 1칸의 요약. 중복되는 별도 날씨 카드는 표시하지 않고, 외출 전 체크의 우산 칸에 오늘 비 오는 시간대를 표시하며, 유효한 예보에 비가 없으면 “오늘은 비 예보가 없어요”로 표시합니다. 확인 전·조회 중·실패·오래된 예보는 비 없음과 구분합니다. 우산 칸 안의 날씨는 밝은 배경 영역에 큰 아이콘·현재 시간대와 날씨 이름을 표시하고, 비 시간대 또는 비 없음 안내를 다음 줄에 분리해 보여줍니다. 우산 칸을 누르면 우산과 날씨 상세로 이동합니다. 우산을 매일 챙겨야 하는 물건으로 집계하지 않습니다.
- 보관 공간: 두 트레이 카드와 별도 우산 공간 카드. 우산 카드 상단은 `SPACE 03` 옆에 우산 상태 칩을 표시하고 아래에 이름을 배치합니다. 이름 아래에는 트레이 카드와 같은 형식의 팬 아이콘·`FAN ON/OFF` 및 살균 아이콘·`살균 ON/OFF`를 표시합니다. 브라우저 미리보기의 팬 상태는 기본 OFF이며, 시간 설정만으로 ON을 표시하지 않습니다. 살균은 실행 중인 상태를 반영합니다. 연결 끊김·수신 대기·센서 오류·오래된 데이터 및 아직 동작 상태 연동 전인 Android에서는 두 상태를 `—`로 표시합니다. 센서 종류와 비 예보 알림 설명은 카드에 표시하지 않습니다. 우산 카드에서 `#umbrella` 화면으로 이동합니다.
- 우산과 날씨: 적외선 센서의 우산 유무·수신 대기·오류 구분, 비 시간대, 위치 갱신 버튼, 예보·위치 확인 시각, 기상청 출처. 조회 실패·불완전한 예보는 비 없음과 구분.
- 우산 건조 팬: 우산 상태 카드 아래에 동작 시간 설정. 0초·15초·30초·1분 중 선택하며 기본 0초는 팬 사용 안 함입니다. 선택 즉시 앱에 저장하고 재실행 시 복원합니다. Android에는 장치 연동 대기를 표시하며, 규격 확인 전 팬 구동 상태나 실행 성공을 표시하지 않습니다.
- 우산 살균: 건조 팬 아래 별도 카드에 활성화·우산 거치 자동 실행·문 열림 실행·0초/15초/30초/1분 설정과 상태 표시. 시간 선택은 항상 가능하며 기본 0초는 살균 사용 안 함으로, 수동·자동 실행을 차단하고 실행 중인 가상 살균을 종료합니다. 양수 시간을 선택하면 활성화합니다. 브라우저는 우산이 있고 활성화된 경우 살균 시작 가능. Android는 설정 저장과 장치 연동 대기를 표시하며 시작 버튼은 비활성화합니다.
- 알림 설정: 기존 순간 문 열림·미수거 알림과 별도로 문 열림 유지 알림 스위치와 1~300초 직접 입력(기본 30초), 비 예보 우산 알림 스위치. 열림 수신 뒤 연결이 끊겨도 닫힘을 확인하지 못하면 한 번 더 안내한다는 설명 표시. 전체 알림 OFF 시 하위 입력 비활성화.
- 시뮬레이션: 우산 유무·적외선 센서 상태·비 예보를 바꾼 뒤 문을 닫았다 열어 검증합니다. 맑음·우산 없음에서는 우산 알림이 없습니다.


## 글자 가독성과 대비

- 모바일 화면 제목 22~25px, 섹션 제목 18~20px, 설정 제목 15~16px, 주요 설명 13~15px를 사용합니다. 별칭·설명은 줄바꿈하며 320px에서도 가로 넘침을 만들지 않습니다.
- 홈 체크의 제목 16px, 카운터 52px, 설명 14px, 트레이 이름 17px, 상태 13px입니다. 날씨 이름은 21px, 비 시간대는 20px, 비 없음·대기 안내는 15px로 표시합니다.
- 물건 있음은 연한 초록색, 없음은 연한 파란색, 수신 대기·오류는 따뜻한 중립색과 상태 문구를 함께 사용합니다. 비어 있는 트레이는 점선 아이콘을 유지합니다.
- 카드 모서리는 기본 20px, 내부 카드와 버튼은 12~15px이며 얇은 경계선과 은은한 그림자로 배경과 구분합니다.
- 주요 버튼 높이는 48px, 뒤로·편집·스위치 입력 영역은 최소 44px입니다. 하단 메뉴는 25px 아이콘과 14px 글자, 선택 배경·상단 표시선, 2.5px 구분선을 사용합니다. 하단 시스템 영역 여백을 유지합니다.
- 예보는 아이콘·날씨 상태, 시간대, 우산 안내, 전체 너비 예보 보기 버튼 순으로 배치합니다. 보조 설명과 업데이트 시각은 구분합니다.
- 기능·설정 저장·Bluetooth·날씨·알림 처리는 기존 데이터 계층을 유지하며, 디자인 변경은 공통 HTML 구조와 CSS에만 적용합니다.

## 최초 실행과 위치 설정

소개 모달은 제거했습니다. 초기 설정을 마치지 않았다면 바로 `#connect`, 저장된 `setupDone`이 있으면 일반 앱 실행 시 `#home`으로 진입합니다. 시스템 알림의 대상 화면 이동은 우선 유지합니다. 브라우저의 명시적인 상세 링크도 유지합니다.

Bluetooth 연결 성공 후에도 위치 카드를 확인할 수 있도록 설정 화면을 유지합니다. “설정 마치고 시작하기” 또는 “나중에 설정하기”가 성공적으로 저장된 뒤 홈으로 이동합니다. 위치는 선택 설정이며, 미허용 상태에서도 트레이 기능은 사용할 수 있지만 위치 확인 전에는 비 예보 우산 알림을 보내지 않습니다. 위치가 꺼져 있으면 “휴대폰 위치 켜기”, 권한을 다시 요청할 수 없으면 “앱 위치 권한 설정”으로 복구합니다. 설정에서 돌아오면 상태를 다시 읽고, 권한·위치가 준비된 경우 현재 위치의 날씨를 조회합니다.
