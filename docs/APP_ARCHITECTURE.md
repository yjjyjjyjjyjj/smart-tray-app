# 아마따 앱 구조

**프로토콜 미확정 — Arduino 펌웨어 분석 후 확정 예정**

웹 UI와 Kotlin의 객체·함수는 앱 내부 도메인 모델입니다. 전송 메시지, Arduino 데이터 포맷 또는 장치 명령 규격이 아닙니다.

## 파일과 역할

| 파일 | 책임 |
| --- | --- |
| `index.html` | HTML5 문서, 앱·모달·상태 알림 마운트, 순차 스크립트 로딩 |
| `css/style.css` | 기존 컴포넌트 구조·동작 상태·전환 스타일 |
| `css/interface.css` | 마지막에 로드하는 공통 디자인: 색상·서체·여백·카드·터치 영역·모바일 및 데스크톱 레이아웃 |
| `js/mock-data.js` | 변경 가능한 앱 이름, 초기 설정, 저장값 검증, 구독형 저장소, 상태 신선도·알림 조건 |
| `js/mock-transport.js` | 가상 검색·연결·문·센서·LED·살균, 활동과 알림 이벤트 |
| `js/native-transport.js` | Android 브리지 어댑터, 네이티브 스냅샷 반영, 체험 모드 전환 |
| `native/bridge.js` | Capacitor 런타임·플러그인 등록 |
| `android/` | Kotlin Bluetooth 서비스·권한·저장소·시스템 알림, Android 패키지 |
| `scripts/build-web.mjs` | 원본 웹 파일과 Capacitor 런타임을 `www/`로 빌드 |
| `js/app.js` | 화면별 렌더 함수, hash 라우터, 이벤트 위임, 모달·토스트, 사용자 입력·설정 저장 |
| `assets/brand/` | 아마따 말풍선·느낌표 브랜드 원본, 웹 표시용 PNG, 단색 SVG |
| `assets/icons/` | 파비콘과 홈 화면 바로가기 아이콘 |
| `assets/images/smart-tray.svg` | 이전 트레이 일러스트 원본 (현재 UI에서 사용하지 않음) |
| `tests/scenarios.test.cjs` | Node 기본 테스트 러너를 이용한 도메인 시나리오 검증 |

스크립트는 IIFE의 네임스페이스로 분리합니다. ES module이나 `fetch`를 사용하지 않으므로 `file://`로 열어도 앱 코드가 동작합니다. 브라우저 목업은 패키지 설치 없이 열 수 있습니다. Android 패키지는 Capacitor·esbuild 의존성을 사용해 빌드합니다. localStorage 사용 가능 여부는 브라우저 정책을 따릅니다.

## 브라우저 상태 계층

Android에서는 `TrayRepository`가 상태·영구 설정·최신 활동 기록 200개를 소유하고 웹 저장소는 표시용 스냅샷을 받습니다. 활동 기록은 SharedPreferences `smart_tray`의 `activities.v1` 키에 저장하며 앱 프로세스 종료 후에도 복원합니다. 실제 Android 기록은 브라우저 체험 기록에 복사하지 않습니다. 네이티브 통신은 UI 타이머나 화면 수명에 의존하지 않습니다. 아래 세션·localStorage 설명은 브라우저/체험 모드에 해당합니다.

브라우저에서는 `SmartTrayData.createStore()`가 앱 상태를 소유하고 `get / update / subscribe / save`를 제공합니다. 렌더러는 저장소를 읽고, 화면 입력은 설정 또는 가상 통신 함수를 통해 변경합니다.

| 상태 | 수명과 책임 |
| --- | --- |
| `preferences` | 연결·위치 설정 완료, 전체·문·미수거 알림, 칸별 이름·알림·LED·살균·기간. localStorage 저장 |
| 연결·수신 | 연결 중·연결·해제, 마지막 수신, 지연 재현 여부. 세션 내 가상 값 |
| `trays` | 고정된 두 칸의 물건·무게·센서·마지막 변경·측정·LED·살균 만료. 저장하지 않음 |
| 문 상태 | 열림·닫힘·미확인, 문 열림 이벤트 번호 및 평가 완료 번호. 세션 상태 |
| 활동 | 최신 200개, 날짜별 표시. `smart-tray.activities.v1` localStorage에 변경 시 저장하고 새 실행에서 복원. 오래된 항목부터 제거 |
| 알림 미리보기·이력 | 최대 50개, 내용·물건·종류·읽음. 세션 한정 |
| 화면 상태 | 현재 경로·트레이, 필터, 모달, 토스트. UI 계층이 관리 |

설정과 활동 기록을 저장하지만 브라우저를 다시 열 때 이전 센서를 실시간으로 복원하지 않습니다. 알림함의 읽음 상태·최근 알림 목록은 기존처럼 세션 한정이며, 기록 → 알림에 쌓인 활동은 200개 한도 내에서 저장합니다. 완료된 사용자는 대시보드를 먼저 표시하고 가상 장치에 자동 연결합니다. 가상 연결 전에 카드는 확인 불가이며, 연결 완료 후 가상 초기 센서값을 받습니다.

저장값은 허용된 필드·타입·기간을 확인하고 기본값과 병합합니다. 이름은 1~16자로 제한하고 HTML 출력에서 이스케이프합니다. 저장 실패는 세션 유지를 허용하고 사용자에게 알립니다.

기본 별칭은 `1번 트레이`, `2번 트레이`입니다. `preferences.schemaVersion = 2`를 사용하며 기존 저장 키는 유지합니다. 이전 버전의 칸별 기본 이름 `지갑 / 자동차 키 / 이어폰`만 번호 이름으로 전환합니다. 그 밖의 사용자 별칭과 모든 설정은 보존합니다. 버전 2에서 사용자가 직접 지정한 이름은 이전 기본 이름과 같아도 그대로 복원합니다.

`trayActivityTitle`과 `trayNotificationMessage`는 트레이 이름 기준의 공통 문구를 만듭니다. `trayDisplayName`으로 활동 기록과 알림의 별칭 뒤에 ‘트레이’를 붙이되 이미 해당 단어로 끝나면 중복하지 않습니다. Kotlin에서도 같은 이름 처리 함수를 센서 활동 기록·실제 알림·시스템 알림 미리보기에 사용합니다. 활동과 알림은 트레이 ID를 참조해 별칭 편집 후에도 현재 이름으로 표시합니다.

## 화면과 설정

라우팅은 hash를 사용해 브라우저 뒤로 가기와 직접 상세 진입을 지원합니다. 홈·트레이·기록·설정이 최상위 탭이며 설정 아래에 알림·장치·앱 정보가 있습니다. `views`의 함수 단위로 각 화면을 분리했습니다.

설정 이벤트는 데이터 속성으로 위임합니다. 이름 변경은 저장 후 카드·상세·장치·알림 설정·기록·알림 내용을 동기화합니다. 브라우저 체험에서 LED·살균 활성화를 끄면 가상 동작 상태도 즉시 정리합니다. Android는 설정을 휴대폰에 저장하며 센서/LED 표시값을 UI에서 임의로 변경하지 않습니다. 하위 옵션은 상위 스위치가 꺼졌을 때 비활성화됩니다.

모달은 별도 DOM 루트를 사용하며 포커스를 순환·복구합니다. 개발자 드로어는 열린 동안 DOM을 유지하고 변경된 텍스트·속성·폼 상태만 반영합니다. 8초 간격 가상 수신 갱신 때 열기 애니메이션을 반복하지 않으며 스크롤·입력 포커스·확정 전 무게 입력을 유지합니다. 실제 상태 변경, 수신 지연과 연결 해제는 계속 표시합니다. `systemNotification()`은 Android 시스템 알림 모양의 카드 컴포넌트입니다. 알림 설정의 예시와 독립된 `#notification-root`의 상단 배너가 이를 공유합니다. 설정 저장 토스트와 알림 배너의 타이머·표시 영역은 분리합니다. 브라우저에서는 Notification API를 사용하지 않고 HTML 카드로 시연합니다. Android에서는 Kotlin이 OS 알림을 생성하며 HTML 상단 알림 배너를 중복 표시하지 않습니다. 알림 클릭은 트레이 ID에 따라 상세·목록·홈을 열고 읽음 처리합니다.

## 가상 통신과 시간

Mock transport는 가상 상태를 직접 변경하는 어댑터입니다. 검색·연결에는 UI 진행을 보여주기 위한 짧은 타이머가 있습니다. 연결 시도 번호를 사용해 취소된 연결의 뒤늦은 완료가 상태를 덮어쓰지 않게 합니다.

가상 연결이 유지되면 브라우저의 8초 간격 타이머로 가상 수신 시각을 갱신합니다. 이는 UI용 heartbeat이며 실제 Bluetooth 통신 주기가 아닙니다. 수신 중단 옵션으로 갱신을 멈추고 45초를 넘긴 상태를 즉시 준비합니다. 45초 역시 UI 검증 기준으로, 실제 장치에서 협의해야 합니다. 무게와 존재 여부는 시뮬레이션에서 독립 입력이며 하드웨어 감지 임계값을 정의하지 않습니다.

연결 → 전체 수신 신선도 → 칸별 센서·측정 신선도 → 존재 여부 순서로 상태를 판정합니다. 연결 해제·수신 대기·오류·지연이면 과거 측정값을 보관할 수 있으나 현재 상태로 취급하지 않습니다. 컵 무게 차감은 Arduino에서 담당하고 앱은 수신한 무게를 표시합니다. 앱의 영점 보정 UI·명령과 중복 무게 차감은 제공하지 않습니다.

LED 미리보기는 2.5초, 살균 동작은 설정 기간 후 종료합니다. 정상 센서와 최신 데이터에서만 시작합니다. 타이머는 어댑터가 소유하며 페이지 종료 시 정리합니다. 문 열림 자동 살균은 물건이 남아 있는 정상 칸에만 적용합니다.

## 알림 판단

닫힘에서 열림으로 바뀌면 이벤트 번호가 증가합니다. 이벤트당 알림 평가를 한 번 수행해 중복을 막습니다. 전체 알림이 켜져 있고 연결·센서가 유효할 때, 미수거·트레이별 설정에 따라 물건이 남은 트레이의 별칭을 모읍니다. 대상이 있으면 하나의 미수거 알림을 만듭니다. 대상이 없고 문 열림 설정이 켜져 있으면 문 열림 안내 하나를 만듭니다. 설정 변경이나 재연결만으로 같은 문 열림 알림을 재생성하지 않습니다.

미리보기 알림은 설정과 무관한 명시적 테스트로 구분합니다. 알림 설정의 실제 조건은 문 열림 또는 A–D 시나리오로 검증합니다.

## 확정한 Android 구조

`WebView UI ↔ Capacitor SmartTrayPlugin ↔ TrayRepository / Kotlin SmartTrayBluetoothService ↔ HC-06 SPP`

UI는 HTML/CSS/JS를 유지합니다. Android 파일·동작·권한·연결 복구·프로토콜 연동 경계는 [ANDROID_DEVELOPMENT.md](ANDROID_DEVELOPMENT.md)에 정리합니다.

- 검색·연결 요청은 화면에서 시작하지만 RFCOMM 소켓과 수신 루프은 서비스가 소유합니다.
- 서비스의 유효한 수신 데이터만 웹 저장소에 반영합니다. 웹 heartbeat는 Android의 수신 시간을 갱신하지 않습니다.
- Android 별칭·알림 설정은 SharedPreferences에 저장되어 UI가 닫혀도 알림 정책에 사용됩니다.
- 프로토콜이 미확정인 현재는 SPP 연결과 센서 수신을 구분합니다. 표준 SPP UUID만 사용하며 센서 패킷/제어 명령을 가정하지 않습니다.
- 체험 모드 진입 시 실제 연결을 해제합니다. 체험 설정은 Android 저장소를 덮어쓰지 않습니다.
- Android 뒤로 가기와 OS 알림 탭 이동을 웹 라우터와 연결합니다.

하드웨어·펌웨어 팀이 측정·노이즈 처리·Bluetooth SPP 송수신·장치 설정 보존·실제 LED 제어·컵 무게 차감을 담당합니다. 자체 서버·FCM은 사용하지 않으며 날씨 조회에는 기상청 API 허브 단기예보조회 API를 사용합니다.

## 세 보관 공간과 조건부 알림

`trays`는 2개만 관리하며 별도 `umbrella`(적외선 유무·센서 상태·측정 시각)와 `weather`(조회 상태·시간·지역 시간대·비 구간)를 추가했습니다. 홈 요약은 세 보관 공간을 표시하고 트레이 수 카운터는 로드셀 트레이 2칸만 셉니다. 우산은 무게 측정과 일반 점등 LED 설정을 사용하지 않으며, 살균 LED 설정은 트레이 1·2번과 독립적인 `preferences.umbrella.effect`에 보관합니다. 우산 건조 팬 시간은 별도의 `preferences.umbrella.fan.duration`(초)에 저장합니다. 0·15·30·60만 허용하며, 기존 설정에 항목이 없거나 잘못된 값이면 0초로 복구합니다. 웹 저장과 Kotlin SharedPreferences에서 같은 규칙을 적용합니다. 이는 제품 설정이며 센서 데이터나 HC-06 전송 규격이 아닙니다. 실제 팬 동작은 아직 연결하지 않았습니다. 우산 살균의 `enabled`·`onDetect`·`onDoor`는 기본 false, `duration`은 일반 트레이와 같은 5·10·20·30초 중 기본 10초이며 웹/Kotlin에서 같은 이관 규칙을 적용합니다. 활성화는 스위치로만 변경하며 OFF일 때 자동 실행과 시간 선택 행을 비활성화합니다. 이전 0·15·60초 등 지원하지 않는 값은 10초·살균 OFF로 전환하되 자동 실행 스위치·팬·별칭을 보존합니다. 유효한 시간과 활성화 설정은 유지합니다. 브라우저만 `umbrella.effectUntil`로 가상 실행을 표시합니다. 실제 앱은 이 값을 생성하거나 미확정 살균 명령을 보내지 않습니다.

문 열림 유지 기준은 `notifications.doorOpenSeconds`이며 브라우저 체험과 Kotlin 서비스에서 같은 10~300초 범위를 사용합니다. 실제 앱의 타이머는 Kotlin에 있습니다. `DoorLeftOpenPolicy`는 UI에 표시되는 최신 센서 상태와 별도로 마지막 열림의 대기를 보관하므로 연결 유실·재연결로 초기화되지 않습니다. 취소·중지와 미확인 상태의 안내 규칙은 [프로젝트 README](../README.md#우산비-예보와-현관문-열림-유지-알림)를 참조하세요. `UmbrellaAlertPolicy`는 닫힘→열림 시 우산 있음·유효 비 예보가 모두 충족되어야 알립니다. 우산 거치·제거는 단독 알림을 만들지 않습니다. 예보는 `WeatherManager`가 대략적 현재/마지막 확인 위치로 조회합니다.


## 트레이 두 칸으로 구성 변경

웹의 `CONFIG.trayIds`와 Kotlin의 `TRAY_IDS`는 1·2번 트레이만 포함합니다. 기존 저장 데이터에서 1·2번 별칭·LED·살균·알림 설정과 공통 알림 설정을 보존하고 3번 트레이 설정은 더 이상 사용하지 않습니다. 우산은 별도 적외선 데이터로 유지하며 3번 트레이 데이터를 우산으로 변환하지 않습니다. 이전 `#detail/3` 주소나 Android 알림 경로는 트레이 목록으로 보냅니다.

홈 외출 전 체크는 두 열의 1·2번 트레이와 그 아래 전체 너비의 우산 공간으로 구성합니다. 본체의 회로 수납부는 앱에 보관 공간으로 표시하지 않습니다.

## 시작 화면과 위치 설정

`js/app.js`는 native hydration 완료 후 첫 화면을 결정합니다. 최초 실행은 `#connect`, 설정 완료 뒤 일반 Android 실행은 `#home`이며 알림 탭 경로가 우선합니다. 초기 소개 모달은 없습니다. 연결·위치 설정에서 위치를 나중에 허용할 수 있으며 `setupDone` 저장 실패 시 완료 처리하지 않습니다.

`SmartTrayPlugin`의 `location` 스냅샷은 `permission`과 `enabled`만 UI에 전달합니다. `refreshWeather`가 COARSE_LOCATION을 요청하고 `WeatherManager`가 실제 위치와 예보를 받습니다. `openLocationSettings`와 `openAppLocationSettings`는 사용자의 버튼 동작으로만 시스템 설정을 열고, 복귀 시 권한/위치 상태를 다시 확인합니다. 위도·경도는 UI 스냅샷에 포함하지 않습니다.
