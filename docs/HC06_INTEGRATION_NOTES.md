# HC-06 Classic SPP 통신과 펌웨어 연동

## 구현 상태

| 영역 | 상태 |
| --- | --- |
| Classic 검색·페어링 목록·시스템 페어링 | 구현. 이름 없는 장치와 LE 전용 장치를 제외하고 주소로 구분 |
| SPP/RFCOMM 연결·스트림·취소·재연결 | 구현. 실제 HC-06 검증은 대기 |
| 포그라운드 서비스·화면과 독립된 수신·저장된 연결 의도 복구 | 구현. 제조사/실기기 백그라운드 검증은 대기 |
| 센서 프레이밍·디코더·장치 제어 명령 | 펌웨어 규격 대기. 구현하지 않음 |
| 센서 도메인·Kotlin 알림 판단·날씨 | 기존 동작 유지. 센서 입력 자동 테스트와 물리 센서 검증을 구분 |

현재 저장소 및 상위 프로젝트 폴더에서 Arduino `.ino`/C/C++ 펌웨어와 실제 메시지 규격을 찾지 못했습니다. 다음 항목을 실제 팀 자료로 확정해야 합니다.

## 장치 선택과 권한

- `listPairedDevices()`는 Android에 이미 페어링된 장치를 표시합니다. `scan()`은 해당 목록에 Classic discovery 결과를 합칩니다. 검색은 최대 15초이며 화면이 백그라운드로 이동하면 검색만 중지합니다.
- 주변 검색과 페어링 목록에는 이름이 `HC-06` 또는 `AMATTA`인 기기만 표시합니다. 앞뒤 공백은 제거하고 대소문자를 포함해 정확히 일치해야 하며, 접두사·접미사가 붙은 이름과 이름 없는 기기는 제외합니다. 검색 중 이름이 다른 값으로 바뀌면 기존 결과에서도 제거합니다. 같은 이름의 기기는 MAC 주소로 구분하고 LE 전용 기기는 제외합니다. 이름 필터 자체가 SPP 지원을 보장하지는 않습니다. 브라우저 체험의 가상 검색 이름은 `AMATTA`입니다.
- 연결 요청은 목록에서 사용자가 선택한 주소만 허용합니다. 이름으로 자동 연결하거나 가까운 장치를 임의로 고르지 않습니다.
- Android 12 이상: 페어링 목록/연결은 `BLUETOOTH_CONNECT`, 새 검색은 `BLUETOOTH_SCAN`도 요청합니다. 검색 결과로 위치를 유추하지 않으므로 `neverForLocation`을 유지합니다. 날씨용 위치 권한은 별도입니다.
- Android 6~11(앱 minSdk 24): 새 검색은 FINE_LOCATION과 켜진 위치 기능이 필요합니다. 이미 페어링된 장치 연결에는 검색용 위치 권한을 요구하지 않습니다. 백그라운드 검색/백그라운드 위치 권한을 추가하지 않았습니다.
- Bluetooth 끄기·권한 거절·지원하지 않는 기기는 오류 문구로 안내합니다. 켜기 버튼은 Android 시스템 확인 창을 사용하며, 휴대폰 Bluetooth 설정 바로가기를 제공합니다.
- 검색·페어링 목록·연결·Bluetooth 켜기 동작에서 필요한 권한을 먼저 요청합니다. 처음 요청하거나 재요청 가능한 거절 상태에서는 Android 권한 창을 띄웁니다. 거절 직후 설정을 강제로 열지 않으며, Android가 재요청을 막은 상태에서 사용자가 다시 시도할 때만 앱 권한 설정으로 이동합니다. 항상 표시되는 앱 권한 설정 버튼은 두지 않습니다. 설정에서 허용한 뒤 다시 검색하면 검색을 진행합니다.
- 선택한 미페어링 장치는 `createBond()`로 **Android 시스템 페어링**을 시작합니다. PIN을 하드코딩하거나 자동 입력하지 않습니다. 해당 주소의 BOND_BONDED 이후에만 소켓을 엽니다. 취소/실패(BOND_NONE)와 60초 초과를 안내합니다.
- 앱의 연결 취소는 늦은 페어링 완료를 무시하여 소켓을 열지 않습니다. 시스템 페어링 창은 OS에서 취소해야 하며 이미 만들어진 페어링을 앱이 임의로 삭제하지 않습니다. 복구 시 페어링이 없으면 사용자에게 다시 선택하도록 안내하고 백그라운드에서 페어링 창을 띄우지 않습니다.

## 표준 SPP와 센서 규격의 구분

`SppProfile.SERVICE_UUID`는 **00001101-0000-1000-8000-00805f9b34fb**로, Bluetooth 표준 Serial Port 서비스 클래스입니다. Arduino 센서 메시지 UUID가 아닙니다. `AndroidSerialSocket`은 `createRfcommSocketToServiceRecord()`로 SDP/RFCOMM 연결을 만듭니다. 고정 채널 1 reflection, 임의 서비스 UUID, 자동 insecure 우회는 사용하지 않습니다.

연결 전 가능한 경우 discovery를 취소합니다(12+에서는 SCAN 권한이 있어야 취소 가능). `BluetoothSocket.connect()`가 성공하고 실제 소켓이 연결된 경우에만 UI를 연결됨으로 표시합니다. [Android RFCOMM API와 표준 SPP UUID](https://developer.android.com/reference/android/bluetooth/BluetoothDevice#createRfcommSocketToServiceRecord(java.util.UUID)), [소켓 연결·취소 동작](https://developer.android.com/reference/android/bluetooth/BluetoothSocket).

`RfcommSession`은 단일 연결/읽기 작업자, 순차 쓰기 작업자, 별도의 타임아웃/닫기 작업자를 사용합니다. 소켓 생성·연결·입출력·close는 메인 스레드 밖에서 수행합니다. 연결 세대 번호로 취소된 연결의 늦은 콜백을 버리고 읽기 루프 중복을 막습니다. EOF·IOException·타임아웃은 소켓을 닫고 서비스에 전달합니다. 쓰기 큐는 최대 16건, 각 요청은 최대 64KiB로 제한하며 연결 해제 시 미완료 요청을 취소합니다. 이는 앱 내부 메모리 제한이지 장치 패킷 크기/규격이 아닙니다.

**소켓 read 한 번 = 센서 메시지 하나로 취급하지 않습니다.** `FirmwareProtocol.feed(chunk)`는 연결별 상태를 갖는 스트림 디코더 경계입니다. 실제 규격이 확인되면 여기에서 제한된 버퍼로 분할/합쳐진 프레임, 인코딩·유효성·순서·오류를 처리해야 합니다. 현재 `PendingFirmwareProtocol.ready=false`이며 모든 바이트를 누적하지 않고 버려 센서값을 생성하지 않습니다. 전송 바이트 수와 유효 센서의 `lastReceived`는 별도입니다. 소켓 연결/수신 자체가 센서 정상 상태를 의미하지 않습니다.

웹 `command`는 미지원 오류를 반환합니다. 내부 소켓 쓰기 기반은 있지만 LED·살균 패킷, 임의 JSON/구분자/초기 상태 조회 명령은 구현하지 않았습니다. 테스트의 스트림 fixture는 테스트 전용이며 실제 펌웨어 규격이 아닙니다.

## 연결 유지·복구·종료

`SmartTrayBluetoothService`가 소켓과 정책을 소유합니다. 사용자 연결 동작으로 `connectedDevice` 포그라운드 서비스 및 연결 유지 알림을 시작합니다. WebView는 상태 구독/바인딩만 정리하므로 앱 전환·화면 꺼짐·Activity 종료가 연결 해제를 지시하지 않습니다. Manifest의 `stopWithTask=false`로 최근 앱에서 화면 제거와 서비스 중지를 구분합니다.

| 조건 | 동작 |
| --- | --- |
| 최초 연결 | 시스템 페어링 최대 60초(필요 시), 소켓 연결 1회 최대 20초 |
| 소켓 연결 실패·EOF·IOException | 최초 시도 뒤 **2·4·8·16초** 대기 후 재시도하고 이후에는 **매 실패 후 30초 대기**를 횟수 제한 없이 반복. 각 소켓 시도 최대 20초이며 시도 시간은 대기 간격과 별도 |
| 소켓 연결 성공 | 재시도 횟수·대기 간격 초기화. 유효 데이터 전 센서는 수신 대기 |
| 장시간 거리 이탈·장치 전원 꺼짐 | 연결 의도와 서비스를 유지하고 30초 대기 후 재시도를 지속. 통신 범위·장치 전원이 복구되면 다음 연결 시도에서 복구 가능 |
| 시스템의 서비스 재생성(`START_STICKY`, null intent) | 저장된 선택 주소와 재시도 횟수를 읽어 복구 시도. 5회 이후에도 30초 대기 간격 유지. 권한/전원/페어링 유효성 확인 |
| 연결 취소·앱 연결 해제·알림의 연결 해제 | 소켓·페어링 대기·재시도 작업·저장된 연결 의도 정리, 자동 복구하지 않음 |
| Bluetooth 꺼짐·연결 권한 해제 | 연결/재연결 중지 및 연결 의도 삭제. 이미 시작한 문 닫힘 확인은 서비스가 살아 있는 동안 남은 기한까지 유지한 뒤 종료. 다시 켠 뒤 사용자가 장치 재선택. OS가 프로세스를 먼저 종료하면 확인 알림을 보장하지 않음 |

연결 의도는 `spp_connection`에 저장합니다. 제품 설정은 기존 `smart_tray`와 웹 저장 키를 유지합니다. 이전 `ble_connection`의 선택 주소는 지워 HC-06으로 오인해 자동 연결하지 않습니다. 별칭·날씨·알림·LED·살균 설정은 삭제하지 않습니다. 연결 성공만으로 초기 설정 완료를 자동 저장하지 않고 사용자의 설정 완료 동작을 유지합니다.

앱 강제 중지/Android 실행 중인 앱의 중지는 콜백 없이 프로세스를 종료할 수 있습니다. 이 경우 수신/복구를 보장하지 않으며, 수동으로 앱을 다시 열어도 연결을 임의로 시작하지 않습니다. 재부팅 후 자동 시작은 미지원입니다. 거리 이탈·장치 전원·제조사 절전 제한에서 무중단 동작을 보장하지 않습니다. [Android 사용자 중지 동작](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping).

## Arduino 팀에서 받아야 할 자료

- [ ] 펌웨어 원본/버전/빌드 환경, 실제 HC-06 보드 버전과 장치 이름·주소·페어링 PIN.
- [ ] UART baud rate·데이터 비트·패리티·정지 비트와 Arduino 직렬 포트 설정, 전원/배선. Android RFCOMM에는 UART baud 설정을 보내지 않습니다.
- [ ] 실제 송수신 원본 바이트 캡처, 문자/바이너리 인코딩, 메시지 경계·길이·체크섬·최대 크기·오류 복구 규칙.
- [ ] 문 개폐, 1·2번 로드셀의 존재/무게/센서 오류, 별도 우산 IR 유무/오류의 필드·단위·범위. 컵 무게 차감·노이즈 처리는 Arduino에서 수행하고, 앱에 전달할 순수 물건 무게와 음수/오차 처리 방식을 확인합니다. 앱 영점 보정 명령은 사용하지 않습니다.
- [ ] 초기 연결/재연결 시 전체 스냅샷 여부, 주기/heartbeat/조회 지원, 순서/중복 처리. 현재 신선도 기준 45초와 호환되는지 확인.
- [ ] 지원되는 LED·살균 명령과 응답/성공/실패/완료, 장치 저장 여부·재부팅 복원, 앱과 장치의 판단 책임.
- [ ] 우산 공간의 살균 LED 시작·정지 명령, 0/15/30/60초 설정(0초는 사용 안 함), 우산 거치/문 열림 자동 실행의 책임, 상태·완료 응답. 앱에는 독립된 설정 저장과 브라우저 시뮬레이션만 구현되어 있습니다.
- [ ] 우산 건조 팬의 시작 조건·정지 조건, 0초(사용 안 함)·15초·30초·60초 설정 명령과 수신 확인, 실제 동작 상태·완료 응답. 앱에는 시간 선택과 로컬 저장만 구현되어 있습니다.

우산 거치/제거 자체로 알리지 않습니다. 닫힘→열림 시 우산 보관 중+정상/최신 IR+오늘 남은 유효 비 예보일 때만 알립니다. 문 열림 유지 시간은 1~300초, 기본 30초이며 Kotlin에서 판단합니다. 유효한 열림 수신 뒤 통신이 끊겨도 닫힘 확인 대기를 유지하며, 연결 유실을 닫힘이나 외출 확정으로 처리하지 않습니다. 전체 정책은 [상위 README](../../README.md#우산비-예보와-현관문-열림-유지-알림)를 참조하세요. 로컬 시스템 알림이며 서버/FCM을 추가하지 않았습니다.
