# 기상청 단기예보 연동

Android의 실제 날씨 공급자는 **기상청 API 허브 `getVilageFcst`**입니다. 브라우저 체험은 가상 날씨를 유지합니다. 이전 Open-Meteo 클라이언트는 제거했습니다. 위치 권한·홈 갱신·Kotlin 시스템 알림 경로는 유지합니다.

## 개발 환경의 인증키

1. [기상청 API 허브](https://apihub.kma.go.kr/apiList.do?seqApi=10)에서 **예특보 → 4.3 단기예보조회**를 활용 신청합니다. `getUltraSrtNcst`는 현재 실황 API이므로 이 신청을 대신하지 않습니다.
2. `android/weather.local.properties.example`을 `android/weather.local.properties`로 복사하고 `KMA_API_KEY`에 API 허브 인증키를 입력합니다. 이 로컬 파일은 Git 제외 대상입니다. CI에서는 같은 이름의 환경 변수를 사용할 수 있습니다(환경 변수 우선).
3. `npm run sync:android` 후 Android Studio에서 저장소 루트의 `android/`를 열어 다시 빌드·실행합니다. 키가 없어도 빌드되지만 실제 조회 시 설정 필요 안내가 표시됩니다.

이 작업 환경에는 발급받은 키를 권한 0600의 로컬 파일로 설정했습니다. 키 값을 문서·저장소·웹 번들·로그에 기록하지 않습니다. 네이티브 `BuildConfig`에 포함되므로 **배포 APK에서 키를 추출할 가능성은 있습니다**. 현재는 메이커톤 시제품의 직접 호출 구조이며, 공개 배포 전 키 노출·호출 한도 관리 방식을 검토해야 합니다. 자체 서버는 추가하지 않았습니다.

## 요청과 위치

- endpoint: `https://apihub.kma.go.kr/api/typ02/openApi/VilageFcstInfoService_2.0/getVilageFcst`
- 인증: `authKey` (공공데이터포털의 `serviceKey`와 구분)
- 매개변수: `dataType=JSON`, `base_date`, `base_time`, `nx`, `ny`, `pageNo`, `numOfRows=1000`
- 앱은 기존 COARSE_LOCATION 권한으로 현재 대략적 위치를 확인합니다. 휴대폰에 마지막 좌표를 저장하고, 공식 Lambert 변환으로 약 5km 격자를 구해 API에는 **격자만** 전송합니다. 지원 범위 밖 좌표는 오류 처리하며 임의의 서울 좌표로 대체하지 않습니다.
- 위치 조회는 Google Play 서비스의 `FusedLocationProviderClient`(대략적 위치·균형 전력)와 Android 통합(fused, Android 12 이상)·네트워크 제공자를 함께 사용합니다. Play 서비스가 없거나 실패해도 플랫폼 경로를 계속 사용하고, 가장 먼저 받은 유효한 결과를 채택한 뒤 나머지를 취소합니다. 2분 이내 최근 위치는 바로 활용하며, 새 위치 요청은 전체 경로를 합쳐 최대 10초 동안 기다립니다. Google 경로도 최근 위치 허용 범위와 10초 요청 제한을 명시합니다. 한 제공자가 실패해도 나머지를 기다리고, 모두 실패하거나 시간이 초과되면 5분 이내의 가장 최근 위치만 대체 사용합니다. 허용 범위를 벗어난 위치는 제외하며, `locatedAt`은 실제 측정 시각을 보존합니다. GPS는 정확한 위치 권한이 이미 있는 경우에만 후보에 포함하고, 날씨를 위해 추가 권한을 요청하지 않습니다.
- 위치 콜백은 요청 시점을 기준으로 5분 이내인 측정값까지 허용하며, 콜백 전달에 실제 소요된 시간만 더합니다(최대 10초). 5분 경계의 정상 응답이 전달 중 수십 밀리초 늦어졌다는 이유로 제외되지 않도록 하는 처리입니다. 타임아웃 시 읽는 플랫폼 캐시는 여전히 조회 시점 기준 5분 이내만 허용하고, 원래 측정 시각을 현재 시각으로 바꾸지 않습니다.
- 홈 날씨 영역·우산 예보·연결과 위치 설정에 **예보 지역**을 시·군·구 수준으로 표시합니다. 날씨 조회에 쓰는 소수점 두 자리의 대략적 좌표를 Android `Geocoder`로 변환하며, 지역명 조회 과정에서 OS 제공 위치명 서비스에 전송될 수 있습니다. 도로명·번지·건물명·원본 좌표는 UI에 전달하지 않습니다. Android 13 이상은 비동기 API, 이전 버전은 별도 작업 스레드를 사용합니다. [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder)
- 지역명 조회는 날씨 HTTP와 독립적으로 진행하고 4초 후 포기합니다. 실패 시 `지역명 확인 불가`를 표시해도 예보는 정상 제공하며, 늦은 응답은 무시합니다. 지역명은 동일한 저장 좌표에만 재사용하고 새로운 위치 요청에서는 이전 지역명을 지웁니다. 대략적인 위치와 Geocoder 특성상 행정구역 경계에서는 실제 위치와 다를 수 있습니다. 브라우저에는 실제 위치가 아닌 **예시 지역**을 표시합니다.
- 홈 진입·홈 재선택·홈에서 앱 복귀 시 매번 조회합니다. 진행 중인 요청만 하나로 합칩니다. 자동 조회는 권한 창을 새로 띄우지 않습니다. 백그라운드 서비스는 마지막 확인 위치를 사용하고 새 위치를 추적하지 않습니다.
- HTTPS 요청은 Kotlin 작업 스레드에서 실행합니다. 연결/읽기 제한은 각각 8초, 응답은 페이지당 2MiB 이하, 최대 5,000행입니다. 페이지를 모두 모은 뒤 검증합니다. 한 번의 화면 갱신이 여러 API 호출을 사용할 수 있습니다.

## 발표 시각과 비 판단

`KmaForecast.kt`는 공식 2026-06 가이드에 따라 **한국 시간 02·05·08·11·14·17·20·23시 발표, 10분 후 제공**을 적용합니다. 새 발표 자료가 `03`(자료 없음)일 때만 직전 발표본으로 한 번 재시도합니다. 권한·한도·통신 오류는 반복 호출하지 않습니다.

강수형태 `PTY`는 0(없음), 1(비), 2(비/눈), 3(눈), 4(소나기)입니다. **1·2·4**를 우산 알림 대상으로 사용합니다. 강수확률만으로 비로 판단하거나 강수량을 임의로 만들지 않습니다. 기상청 날씨/강수형태의 19:00 값은 **18:00–19:00** 구간을 나타냅니다. 연속된 구간은 합치고, 이미 지난 구간·내일 구간을 오늘 알림에서 제외합니다.

오늘 남은 모든 시간의 PTY가 있어야 유효한 예보로 인정합니다. 잘못된 값·누락·상충 중복·요청과 다른 격자/발표본·불완전한 페이지는 오류입니다. 조회 후 1시간이 지났거나 한국 시간 자정을 넘기면 다시 확인해야 합니다. 인증/활용 승인, 한도, 위치, 자료 없음, 불완전한 응답, 네트워크 오류를 화면에 안내합니다. 오류를 “오늘은 비 예보가 없어요”로 표시하지 않습니다.

하늘상태 `SKY`는 1(맑음), 3(구름 많음), 4(흐림)을 사용합니다. 강수형태가 비·비/눈·눈·소나기이면 해당 상태를 우선 표시합니다. 홈 우산 칸과 날씨 상세 화면에는 **현재 시간대의 예보**를 보여주며, 실시간 관측이나 오늘 전체의 대표 날씨로 표시하지 않습니다. 오늘 남은 비 예보가 있으면 기존 비 시간대 안내가 우선입니다. 비가 없을 때도 눈·구름 정보를 구분하며, SKY 누락을 맑음으로 간주하지 않습니다. 브라우저 시뮬레이션의 가상 날씨 선택에서 각 상태를 체험할 수 있습니다. [기상청 단기예보 코드 안내](https://data.kma.go.kr/data/rmt/rmtList.do?code=420&pgmNo=572)

`RainHour`는 비 포함 여부와 날씨 상태를 보관하고 `RainForecast`는 유효 시간과 시간대를 관리합니다. 알림 조건은 기존과 같습니다: 닫힌 문 → 열림, 유효한 우산 센서가 보관 중, 알림 설정 켜짐, 유효한 오늘 남은 비 예보. 판단과 Android 로컬 시스템 알림은 Kotlin에서 처리하며 FCM을 사용하지 않습니다. 우산을 넣거나 꺼내는 동작만으로 알림을 만들지 않습니다.

## 검증과 한계

- API 허브 실제 승인 확인: 공개 서울 격자(60,127), HTTP 200, `resultCode=00`. 사용자 휴대폰 위치를 이용한 요청이 아닙니다.
- `KmaForecastTest`: 격자, 발표 시각·날짜 경계, 페이지 합치기, 강수형태·시간 구간, 불완전한 데이터, 오류/재시도, 우산 알림 조건을 가상 응답으로 검증합니다.
- `WeatherLocationTest`: 고정된 Android 테스트 위치 → 격자 요청 → WebView와 홈 갱신. 모든 HTTP를 로컬 응답으로 대체합니다.
- `WeatherRegionLookupTest`: 행정구역 정리, 빈 응답·서비스 오류·시간초과·늦은 응답·요청 취소를 검증합니다. `WeatherRegionLiveTest`는 `regionLive=true`로 명시적으로 실행할 때만 공개 서울 좌표를 실제 Geocoder에 조회하며, 휴대폰 위치·권한·설정을 바꾸지 않습니다.
- `KmaLiveApiTest`: 아래 명시적 실행에만 공개 서울 위치로 실제 기상청을 조회합니다. 실제 API 호출 한도를 사용합니다.

```sh
cd android
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=kr.ac.gachon.smarttray.KmaLiveApiTest \
  -Pandroid.testInstrumentationRunnerArguments.kmaLive=true
```

실행 결과와 기기 검증 범위는 [VALIDATION.md](VALIDATION.md)에 기록합니다. 실제 휴대폰에서 COARSE_LOCATION 권한으로 최근 위치를 활용해 기상청 조회와 화면의 확인 완료 표시까지 검증했습니다. 실제 HC-06 센서에서 우산 알림까지의 경로는 별도 실기기 검증 대상입니다.

공식 기준: [API 허브](https://apihub.kma.go.kr/apiList.do?seqApi=10), [단기예보조회서비스 가이드](https://apihub.kma.go.kr/getAttachFile.do?fileName=단기예보조회서비스_API활용가이드_260623.docx), [기상청 시간대별 예보 설명](https://www.weather.go.kr/wnuri_help/html/weather/short-term.jsp).

개발 빌드의 `AmattaLocation` 로그에는 제공자 이름, 응답 유무, 위치 경과 시간만 기록합니다. 좌표·지역명·인증키·요청 URL은 기록하지 않으며, 릴리스에서는 이 진단 로그를 출력하지 않습니다. 대략적 위치는 OS/Google 서비스에서 갱신 빈도가 제한될 수 있어, 설정이 켜져 있어도 새 측정값을 기한 내 받는다고 보장하지 않습니다. [Google 대략적 위치 동작](https://developers.google.com/android/reference/com/google/android/gms/location/FusedLocationProviderClient)
